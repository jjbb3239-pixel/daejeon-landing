**1인 게시 전제.** 여러 계정으로 나눠 올리는 방식을 쓰지 않는다.

```
전환 = mood_test_complete (기분 테스트 4문항 완료)
목표 = 세션 최대화 + CVR ≥ 2%
```

## 1. A/B 설계 — 1인 계정으로 할 수 있는 유일한 방법

계정이 하나면 "같은 시각에 두 문구"를 못 올린다. 그래서 **교차 설계(crossover)** 를 쓴다.

```
            점심 슬롯 (12:30)    저녁 슬롯 (20:30)
9/4 (금)         A                    B
9/5 (토)         B                    A      ← 순서를 뒤집는다
9/6 (일)         A                    B
```

A 를 두 슬롯에 걸쳐 합산하고 B 도 같이 합산하면 **시간대 효과가 상쇄된다.**
하루 한 번씩 번갈아 올리면 요일 효과에 오염되므로 이렇게 한다.

### 검증 변수는 하나만 — 훅 유형

두 개 이상 바꾸면 무엇이 이겼는지 알 수 없다. 바꾸는 건 **첫 문장의 훅 유형** 뿐이고,
링크 · 이미지 · CTA 문구 · 게시 시각은 전부 고정한다.

| | 훅 유형 | 노리는 심리 | 첫 문장 예 |
|---|---|---|---|
| **A** | 문제 공감형 | "내 얘기다" | "대전 가서 뭐 할지 검색하는 데 30분 썼어요" |
| **B** | 결과 호기심형 | "내 결과가 궁금하다" | "대전 여행 스타일, 넷 중에 어느 쪽이세요?" |

**둘 다 전환 행동을 약속한다.** 어느 쪽도 일부러 나쁘게 만들지 않았다.
정말 모르는 것을 물어야 A/B 다.

### 채널은 스레드 하나만

X 까지 A/B 하면 표본이 반으로 쪼개진다. **스레드에서만 검증하고, X 는 승자를 받아 쓴다.**
스레드를 고른 이유는 알고리즘이 비팔로워에게도 뿌려서 1인 계정에서도 볼륨이 나오기 때문이다.

### 같은 문구를 반복하지 않는다

3일 × 2슬롯 = 6개를 올려야 한다. **훅 유형은 고정하고 표면 문장만 바꾼다.**
A 는 공감 훅 3종, B 는 호기심 훅 3종을 준비해 슬롯마다 다른 걸 쓴다.
그대로 복붙하면 스레드가 반복 게시로 보고 도달을 줄인다.

## 2. 표본 현실 — 먼저 인정하고 시작한다

1인 계정 3일이면 변형당 세션 **30~150** 이 현실이다. CVR 10% 라면 변형당 전환 3~15개.

> **이 규모에서는 통계적 유의성이 나오지 않는다.** 그래도 하는 이유는 세 가지다.
>
> ① 문구 결정을 감이 아니라 데이터로 하는 절차를 만든다
> ② CMO 보고에서 "검증 설계를 하고 운영했다"가 방어된다
> ③ **명백한 참패는 3일이면 보인다.** 2배 이상 차이는 이 표본에서도 드러난다

### 판정 규칙 — 미리 정한다. 감으로 판단하지 않는다

```
판정 시점 : 9/6 (일) 밤

1) 어느 한쪽 CVR < 2%  →  그쪽 탈락. 반대쪽 채택
2) 둘 다 2% 이상       →  전환 수가 많은 쪽 채택
3) 차이가 1.5배 미만    →  무승부. 세션이 많은 쪽 채택 (방문수도 목표이므로)
4) 둘 다 세션 30 미만   →  판정 불가. A 를 유지하고 9/9 에 다시 본다
```
